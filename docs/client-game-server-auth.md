# Client Authentication With The Game Server

This document describes how the desktop client currently authenticates to the legacy game socket server.

## Scope

- Client code: `src/Client/java/client/Launcher.java`, `src/Client/java/view/View.java`
- Game server code: `src/GameServer/java/server/HackerServer.java`, `src/HackWars/java/game/Computer.java`
- Transport library: `src/HackWars/java/com/plink/dolphinnet/*`

The protobuf/JWT transport in `src/Networking` is not wired into the runtime game login path yet.

## Authentication Flow (Current Runtime)

1. Launcher login UI collects `username` and `password` and calls `View.loginToServer(...)`.
2. `View.reconnect()` opens DolphinNet sockets to the game server:
   - client outbound -> server receive: `10020`
   - server outbound -> client receive: `10021`
3. During socket bootstrap, server assigns a reporter connection ID by sending an `Integer` message.
4. Client initializes Diffie-Hellman (`Encryption.getInstance().init()`), then creates `LoginAssignment`:
   - `user = username.toLowerCase()`
   - `pass = XOR(password, clientHash)`
   - `ip = selected player IP`
   - `publicKey = client DH public key`
5. `clientHash` comes from `Assignment.hash`, populated by `HashSingleton.getHash()` (random 10-char process-local string).
6. Server receives `LoginAssignment` and reads `clientHash` from `Assignment.getHash()`.
7. Server de-obfuscates password via `Computer.crypt(pass, clientHash)` and runs `Computer.checkLogin()`:
   - validates username/password against MySQL
   - validates that account IP matches the requested in-game IP
   - may allow local fallback auth if configured (`hackwars.localAuthFallback`)
8. If valid, server sends `LoginSuccessAssignment(ip, encryptedIP, npc)` and may include server DH public key.
9. Client receives `LoginSuccessAssignment`, calls `Encryption.getInstance().finalize(serverPublicKey)`, and starts the main game UI.
10. If invalid, server sends `LoginFailedAssignment` and client returns to login state.

## What `encryptedIP` Is

`encryptedIP` is a per-login random token (10 chars) generated by `HackerServer.getRandomKey(...)`.

- Server stores mapping: `(encryptedIP + clientHash) -> realIP`
- Client uses `encryptedIP` in most `RemoteFunctionCall` parameter payloads instead of raw IP.
- Server resolves it with `HackerServer.crypt(token, clientHash)`.

If lookup fails, server currently falls back to the provided string unchanged.

## Post-Login Request Protection

After login success:

- `RemoteFunctionCall` includes both:
  - plaintext `function`
  - encrypted `byteFunction` (DES from DH key exchange)
- Server tries to decrypt `byteFunction`; if decrypt fails, the plaintext `function` field can still be present.
- Parameters are mostly not encrypted at transport level; IP-like fields are tokenized via `encryptedIP`.

## Optional Pre-Check In Launcher

`Launcher` supports optional remote XML-RPC login (`remoteAuth=true`) before socket login:

- check-date call: `checkDateRpcURL`
- login call: `loginRpcURL`
- can return alternate player IP

This is a gate/check step in the launcher, not the game socket server authentication itself. If remote auth is unavailable, launcher falls back to local mode.

## Important Notes

- Transport is Java object serialization over raw TCP sockets (legacy DolphinNet), not TLS.
- Password handling on the game socket path is XOR obfuscation with `clientHash`, not modern password-auth protocol.
- JWT-based auth exists only in the `:Networking` module plans/tests and is not yet active for game login.
